# 0단계 — 바탕 (먼저 끝내야 한다)

**이게 안 고쳐지면 어떤 모션도 평가할 수 없다.** 2026-09-10 에 옆모습 팔이 아예
배정 안 돼 있는 걸 모르고 「팔이 V자로 굳었다」를 여러 바퀴 논의했다.

- [ ] #d1 [바탕] **AI 에게 준 뼈대와 그림을 자르는 뼈대가 서로 다르다 (옆모습).**
  읽을 것: `docs/CHARACTER.md`

  **뼈대는 그림에서 뽑는 것이 아니라 숫자에서 계산된다.** 그리고 같은 숫자로 두 가지를
  만든다 — ① `comfy.figure()` 가 ControlNet 용 뼈대 그림을 그려 **AI 에게 이 자세로
  그리라고 시키고**, ② `rig.joints()` 가 같은 좌표로 **그 그림을 부품으로 자른다.**
  같은 숫자에서 나오니 맞아야 하는데, **두 함수가 옆모습에서 다르다:**

  | | `comfy.figure()` (AI 에게 준 것) | `rig.joints()` (자를 때 쓴 것) |
  |---|---|---|
  | 정면 어깨 반폭 | `h*0.105` = 44.1px | `h*0.105` = 44.1px — 같다 |
  | **옆모습 어깨 반폭** | **`H*0.12` = 14.0px** | **`h*0.105` = 44.1px** — **30.1px 다르다** |
  | **옆모습 골반 반폭** | **`H*0.10` = 11.7px** | **`h*0.070` = 29.4px** — **17.7px 다르다** |
  | **옆모습 팔을 몸 앞으로** | `fr = h*0.035` = 14.7px · `fl = h*0.015` = 6.3px | **아예 없다** |

  `comfy.figure()` 는 옆모습에서 어깨·골반을 **일부러 접는다.** 주석에 이유가 있다 —
  *"폭이 같으면 프롬프트에 side view 를 넣어도 정면을 그린다(실측)."* 그리고 옆모습은
  **두 팔이 같은 쪽(앞)으로** 가야 해서 `fr`/`fl` 로 앞으로 민다.
  **`rig.joints()` 는 이 셋을 하나도 안 한다.**

  그래서 AI 는 접힌 어깨로 옆모습을 그렸는데, 자를 때는 안 접힌 뼈대를 대고 잘랐다.

  **실측 (칸 중심 cx=768 기준 오른 어깨 x):**

  | | x |
  |---|---|
  | AI 가 받은 뼈대 | 782.0 |
  | 자를 때 쓴 뼈대 | **812.1** |
  | 그림의 팔이 실제로 있는 자리 | **767** |

  그 결과 `split()` 이 아래팔에 배정한 픽셀이 **0개**다:

  | 어깨 반폭 | 위팔 | 아래팔 | 몸통 |
  |---|---|---|---|
  | 44.1px (지금) | 850 | **0** | 8,103 |
  | 12.6px | 1,972 | 1,183 | 4,090 |
  | 0.0px | 1,550 | **1,583** | 3,349 |

  **고칠 것 — 값을 새로 지어내지 마라. 두 함수를 일치시켜라.**
  `rig.joints()` 가 `comfy.figure()` 와 **같은 식**을 쓰게 한다: 방향을 인자로 받아
  옆모습이면 `sw = H*0.12`, `hw = H*0.10`, 그리고 `fr`/`fl` 로 두 팔을 앞으로 민다.
  **`comfy.figure()` 를 고치면 안 된다** — 그걸 바꾸면 밑그림을 다시 뽑아야 한다.

  **두 함수가 갈라지지 않게 하는 것이 이 항목의 절반이다.** 한쪽에 모아서 다른 쪽이
  불러 쓰게 하거나, 안 되면 **같은 값인지 검사하는 QA** 를 둔다.

  자체 QA: **새 검사 둘** —
  ① 「부품마다 뼈 반경 안의 그림 픽셀 수가 0 이 아닌가」(세 방향 전부),
  ② 「`comfy.figure()` 와 `rig.joints()` 가 같은 관절 좌표를 내는가」.

- [ ] #d2 [바탕] **부품을 떼어낸 자리에 몸통 구멍이 남는다.**
  그림에서 팔이 **몸통 위에 겹쳐** 그려져 있어서, `split()` 이 팔을 가져가면 그 아래
  몸통이 원래 없다. 팔이 몸 밖으로 나가는 순간 구멍이 뚫린다(`#d1` 을 고친 뒤 옆모습
  use 프레임에서 확인).
  **고칠 것**: `split()` 뒤에 구멍 메우기 — 이웃한 같은 부품 픽셀로 채운다.
  자체 QA: **새 검사** — 쉼 자세에서 부품을 다 합친 알파 == 원본 알파.

- [ ] #d3 [바탕] **정면·뒷모습도 뼈가 그림의 팔에 얹혀 있는지 확인한다.**
  `#d1` 은 옆모습만 쟀다. 정면·뒷모습은 뼈가 **몸 테두리 안에는** 있지만 그게 곧
  **팔 위**라는 뜻은 아니다. `#d1` 이 만든 검사를 세 방향에 돌려 값을 남긴다.

- [ ] #d4 [바탕] **프레임 사이 변화에 상한만 있고 하한이 없다.**
  정면 걷기가 프레임당 **1.4~2.3%** 만 바뀌는데 통과한다. 「이어짐」 상한은 팔레트가
  프레임마다 달라지던 옛 버그(56%)용인데, 지금은 **움직임을 눌러버리고 있다.**
  하한을 더한다 — 값은 실측으로 정한다.

- [ ] #d5 [바탕] **걷기에서 몸이 위아래로 한 픽셀도 안 움직인다.**
  정면 걷기 6프레임에서 **머리 꼭대기 y 가 내내 0, 발밑이 내내 95.** `walk_front()`
  /`walk_side()` 에 몸통 상하 값이 아예 없다.
  **주의**: 옛 컷아웃에서 `bob=1` 을 넣었다가 **머리만 46.5% 흔들려** 뺀 이력이 있다.
  이번에는 **몸 전체가 같이** 내려가야 한다.
  자체 QA: 「걷기에서 머리 꼭대기 y 의 최대-최소가 0 이면 불합격」.

- [ ] #d6 [바탕] **시트를 레이어로 나눈다 (페이퍼 돌).**
  **`#d7`(전부 다시 굽기)보다 먼저 해야 한다** — 안 나누고 구우면 나중에 22장을 또 굽는다.
  읽을 것: `docs/CHARACTER.md` **5-c** (결정과 근거, 조사 결과가 다 거기 있다)

  지금은 몸·옷·도구가 **한 장으로 합쳐져** 구워진다. 색은 실행 중에 바꿀 수 있지만
  (`CHARACTER.md` 5-b) **모양이 다른 옷**(긴팔·코트·갑옷)은 못 넣는다. 시트로 나누면
  조합이 곱해진다 — 지금 22장 × 머리모양 4종 = 88장인데 옷 5벌이면 **440장**이다.

  **바꿀 곳은 두 군데뿐이다.** 부품 10개와 재질 라벨은 **이미 픽셀을 따라다닌다**:

  ```
  부품 10개 + 재질 라벨       ← 이미 분리돼 있다
     ↓ bake_rows()            ★ 재질 마스크를 걸어 레이어별 시트를 굽는다
     ↓ add_ink()              ★ 옷 레이어는 레이어마다, 도구는 합친 뒤 한 번
  ```

  **레이어 여섯으로 출발한다**: ① 몸 ② 머리 ③ 상의 ④ 하의 ⑤ 신발 ⑥ 도구.
  (표준 자산은 20장까지 쓰지만 액세서리·양말·효과까지 나눈 것이다 — 필요할 때 늘린다.)

  **철칙 하나만 지키면 된다** — *"모든 레이어가 몸 시트와 똑같은 격자에 놓인다."*
  우리 22장은 이미 **같은 테두리·같은 팔레트**로 굽고 있으므로(`bake_rows` 주석)
  저절로 지켜진다. 레이어를 나눠도 **테두리 계산은 합친 실루엣 기준으로 한 번만** 한다.

  **잉크는 옷과 도구를 다르게 다룬다** — 옷은 소매 끝·옷깃이 **보여야** 하므로 레이어마다,
  도구는 몸 **앞을 지나가므로** 지금처럼 합친 뒤 한 번(미리 두르면 스티커가 된다).

  **범위 밖**: 새 옷을 실제로 그리는 것. 밑그림에 반팔 한 벌뿐이라 **분리해도 긴팔은
  안 생긴다.** 그 그림을 어디서 받을지는 `CHARACTER.md` 5-c 에 두 길만 적어뒀고
  사람이 나중에 정한다.

  자체 QA: **새 검사** — 「레이어를 전부 겹친 것 == 합쳐서 구운 것」(픽셀 단위로 같아야
  한다). 엔진 쪽에서 레이어를 쌓는 것은 이 항목 범위 밖이고 `INBOX` 항목으로 넘긴다.
