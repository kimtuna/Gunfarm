**전 회차에서 그대로 둔 것**
- **덤불 하나의 크기** — 잎 8~14px · 굵기 2~3px · 한 덤불에 포기 5~7개.
  `INBOX #62` 가 값을 치르고 올린 값이고, 큐가 *"줄이지 말 것"* 이라고 못 박았다.
  한 개도 안 건드렸다.
- **덤불로 모으는 것 자체**(`CLUMP_SPREAD = 0.13`) · 퍼짐 값.
- **바다** — 물결·개수·뿌리는 방식 전부 그대로. 큐: *"바다는 건드리지 않는다."*
- 팔레트·램프·타일 규격.

**보완한 것**
큐의 지적 *"`INBOX #62` 가 잡티를 덩어리로 만든 것까지는 옳았다. 틀린 것은 그 덩어리를
칸마다 똑같이 하나씩 놓은 것이다"* 때문에, **덤불의 크기가 아니라 「수」를 변주마다
벌렸다** — `gen_terrain.GRASS_CLUMPS = (0, 1, 1, 2, 1, 3, 1, 2)`.
- **0 이 한 종 있다.** 전부 1개 이상이면 화면에 빈 데가 없어서, 자리를 아무리 흔들어도
  밀도가 고르게 보인다 — 그게 지금까지의 문제였다.
- **0 을 여럿 두지 않았다.** 8종 중 둘이 비면 25% 가 민무늬라 이번엔 땜빵으로 보인다.

**재본 값** (r0 → r1)
| | r0 | r1 |
|---|---|---|
| 변주별 덮인 넓이 | 18.4 ~ 24.9% | **0.0 ~ 50.0%** |
| 폭 | 6.5% | **50.0%** |
| 「이음매」 땅 (상한 1.10) | 0.94 | **0.89** (더 안 보인다) |
| 「이음매」 바다 (상한 0.80) | 0.61 | 0.61 (안 건드렸다) |
| 「무늬」 grass | 79% / ±9.5 | 75% / ±10.8 |
| 「무늬」 sea | 79% / ±10.9 | 79% / ±10.9 |
| 「캐릭터대비」 | 61% | 61% |

**새로 만든 자**: `qa_sprite_check.py` 의 **「변주폭」**.
「변주」·「무늬」·「이음매」가 셋 다 초록불인 채로 이 문제가 지나갔다 — 「변주」는 8종의
바이트열이 다르기만 하면 통과하고, 「무늬」는 8종을 뭉쳐 평균만 본다.
**검사가 진짜 잡는지 확인했다**: `GRASS_CLUMPS = (1,)*8` 로 옛 그림을 다시 구워
돌리니 다른 검사는 전부 초록불인데 「변주폭」만 FAIL 이었다
(*"폭 7% < 하한 30%"*).
