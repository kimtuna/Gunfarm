## 실측 — `th` 는 66 벌 전부 한 값이다

`gen_player._grid()` 의 `th` 는 **칸 안에서 인물이 쓰는 줄 수**다. 22장 × 3방향
(down/left/up — right 는 left 의 거울이라 굽지 않는다) = **66 벌 전부 `70px`**,
즉 `FIG` 72 − 2×`PAD` 1 이다. **세로를 깎인 시트가 하나도 없다.**

깎이는 조건은 `_grid()` 의 `tw > cell - 2*pad`(94px) 한 줄인데, 실제 `tw` 는:

| | 시트 | `tw` |
|---|---|---|
| 가장 넓다 | `hold`·`walk`·`use_gun` 정면 | **73px** (상한 94px — **21px 남음**) |
| 그다음 | `use_sickle` 정면 | 69px |
| 가장 좁다 | `walk_watering_can` 옆모습 | 35px |

인물 키가 96px(칸을 꽉 채우던 때)이던 동안 총이 86px · `use_sickle` 이 87px 로
깨져 있던 것은 **칸에 여유가 0 이었기 때문**이고, 72px 로 내려 24px 이 남으면서
그대로 사라졌다. **항목이 예측한 「네 번째 길」이 맞았다** — (가) 칸을 넓히는 대가를
치를 일이 없다.

### 재는 법 — 파일을 한 장도 안 쓴다

옆에서 그림 루프가 돌고 있어서(이번엔 `#d2` 초원) **작업 트리를 건드리면 안 된다.**

- `gen_player._grid` 를 가로채 `(th, tw, box)` 를 기록하고, `rig.bake_rows` 를 감싸
  호출한 쪽 프레임(`sys._getframe(1).f_locals`)에서 `motion`/`d` 를 읽어 이름을 붙였다.
- `PIL.Image.Image.save` 를 빈 함수로 바꿔 `rig.build_sheets()` 를 돌렸다. 약 2분.

### **저장소의 22장이 지금 코드가 굽는 것과 바이트까지 같다**

잰 `th` 가 「코드가 만들 값」이 아니라 **실제로 저장소에 들어 있는 시트의 값**임을
따로 확인했다. `Image.Image.save` 를 임시 폴더로 **돌려서** 다시 굽고 md5 를 견줬다 —
**22/22 같음.** (작업 트리에는 한 글자도 안 썼다.)
