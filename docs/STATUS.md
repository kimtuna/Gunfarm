## 만든 것

- **월드의 일시정지 메뉴** — `world.tscn` 의 `HUD/PauseMenu`(계속하기 / 설정 /
  메인 메뉴로 나가기), 여는 쪽은 `world.gd` 다. Esc 는 이제 슬롯으로 나가지 않는다.
- **월드는 멈추지 않는다** — `get_tree().paused` 를 쓰지 않았다. 끊는 것은
  `player.gd` 의 `input_enabled` 하나뿐이고, 그건 이동만 0 으로 만들고 **조준 각도는
  보던 값을 유지**한다(0 으로 넣으면 메뉴를 열 때마다 캐릭터가 홱 돈다 — 지난 바퀴
  메모 그대로였다).
- **설정은 씬 전환이 아니라 월드 위에 겹쳐서 띄운다** — `settings.gd` 에 `as_overlay`
  를 넣고 `HUD` 에 붙인다. 씬을 바꾸면 월드가 통째로 내려가서 "월드는 멈추지 않는다"가
  애초에 성립하지 않는다.
- **Esc 는 가장 안쪽 창부터 닫는다** — 설정 → 일시정지 메뉴 → (없으면) 열기.
  겹쳐 뜬 화면은 **자기 Esc 를 처리하지 않는다**(띄운 쪽이 닫는다). 양쪽이 다
  처리하면 Esc 한 번에 두 창이 닫힌다. #18(맵)이 이 자리에 그대로 붙는다.
- **뒤로 버튼 4개 제거** — `world` / `character_slots` / `character_customize` /
  `settings` 의 `BackButton` 과 짝이 되는 `_on_back_pressed`. 그 자리에는
  **"Esc — 돌아가기" 안내 라벨**만 남겼다(버튼이 아니다).
- **검사 갱신**(INBOX #17 (4)):
  - `qa_world_entry.gd` — Esc 가 슬롯으로 안 나가고 메뉴를 여는지 / `paused` 를
    안 썼는지 / **월드에 시계(Timer)를 걸어 메뉴가 열린 동안에도 시간이 흐르는지** /
    W 를 누른 채로 안 움직이고 닫으면 다시 움직이는지 / 설정이 겹쳐 뜨고 Esc 로
    안쪽만 닫히는지 / "메인 메뉴로 나가기"가 슬롯이 아니라 메인 메뉴로 가는지.
  - `qa_main_menu` / `qa_character_slots` / `qa_settings` / `qa_character_customize`
    — 화면 전환을 뒤로 버튼이 아니라 Esc 로 하고, 네 화면 모두 **뒤로 버튼이
    되살아나지 않았는지**(이름으로도 글자로도) 검사한다.

## 스스로 판단해서 고친 부분

- **일시정지 메뉴를 별도 씬/스크립트로 빼지 않고 `world.tscn` + `world.gd` 안에 뒀다.**
  월드 말고는 쓸 데가 없고, #18 의 맵도 같은 자리에 겹쳐 붙으면서 "가장 안쪽 창부터
  닫는다"는 순서를 한 함수(`_unhandled_input`)에서 정해야 하기 때문이다.
- **겹쳐 뜬 설정이 자기 Esc 를 처리하지 않게 했다.** 처음엔 양쪽이 다 처리하게 뒀는데,
  그러면 어느 쪽이 먼저 받느냐(전파 순서)에 동작이 달렸고 잘못하면 Esc 한 번에 두
  창이 닫힌다. 닫는 책임을 띄운 쪽 하나로 몰아서 순서와 무관하게 만들었다.
- **뒤로 버튼 자리에 "Esc — 돌아가기" 라벨을 넣었다.** 지시는 버튼을 없애라는 것이지만,
  되돌아가는 유일한 길이 화면에 아무 흔적도 없으면 갇힌 것처럼 보인다. 라벨은 버튼이
  아니므로 「화면 안의 뒤로 버튼은 두지 않는다」와 어긋나지 않는다.
- **`qa_world_entry.gd` 의 기다림을 프레임이 아니라 시간 기준으로 바꿨다**
  (`SETTLE_SECONDS`). 아래 「어려움」 참고 — 안 고치면 이번에 새로 만든 검사가 이가
  없는 채로 통과한다.

## 어려움 / 에러와 해결

- **새 검사가 처음엔 이가 없었다.** "메뉴가 열려 있으면 W 를 눌러도 안 움직인다"가,
  실은 **아무도 안 움직여서** 통과하고 있었다 — `--script` 창은 수직동기화가 없어
  몇 프레임이 몇 ms 라 고정 틱(1/60초)이 한 번도 안 돈다(`docs/GOTCHAS.md` 에 이미
  적혀 있는 함정이다). 기다림을 `_wait_time`(초)으로 바꿔서 해결했고, 고친 뒤
  **일부러 망가뜨려 이가 있는지 확인했다**: (1) `input_enabled` 를 항상 켜두면
  "메뉴가 열려 있는데 24.0 만큼 움직였다" FAIL, (2) `get_tree().paused = open` 을
  넣으면 "세계를 세웠다" + "한 틱도 안 흘렀다" FAIL. 둘 다 원복 후 재통과.
- **같은 함정이 `qa_world_entry` 의 옛 검사도 이미 깨뜨리고 있었다** — "같은 시드로
  다시 들어왔는데 화면이 다르다". 캡처 시점에 틱이 한 번도 안 돌아서 캐릭터가 아직
  마우스 쪽을 안 본 채로 찍혔던 것이다. 같은 시간 기준 대기로 같이 고쳤다.
