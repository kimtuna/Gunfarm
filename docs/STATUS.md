## 한 일 — 지시대로 두 값을 같이 바꿨다

| 곳 | 전 | 후 |
|---|---|---|
| `project.godot` `window/size/viewport_*` | 1280×720 | **1440×810** |
| `scripts/settings_store.gd` `BASE_SIZE` | 1280×720 | **1440×810** |

`stretch mode=canvas_items` / `aspect=keep` 은 안 건드렸고, `RESOLUTIONS` 목록도
그대로다(지시 (1)(2)). 실측으로 **30.0×16.9 타일**이 되어 스타듀와 같아졌고, 캐릭터가
화면 세로에서 차지하는 비율은 13.2% → **11.9%** 다.

## 지시에 없었지만 반드시 필요했던 것 — **`DEFAULT_SIZE` 를 새로 갈랐다**

**1440×810 은 `RESOLUTIONS` 에 없는 값이다.** 그런데 `default_settings()` 가 `BASE_SIZE`
를 기본 창 크기로 쓰고 있어서, 그대로 두면 **설정 화면이 목록에 없는 값을 기본값으로
보여주고**(`_options.find(current)` 가 −1 → 0 번으로 튄다) 창 크기와 화면 표시가
어긋난다. 그래서 `settings_store.gd` 가 두 값을 따로 갖게 했다:

- `BASE_SIZE` = **1440×810** — 논리 해상도(= 보이는 월드 범위).
- `DEFAULT_SIZE` = **1280×720** — 기본 창 크기. 반드시 `RESOLUTIONS` 안의 값이어야 한다.

`project.godot` 에 `window/size/window_*_override = 1280×720` 도 같이 넣었다 — 없으면
창이 1440×810 로 떴다가 메인 메뉴에서 1280×720 으로 튄다. 근거는 `DESIGN.md`
「카메라 / 해상도」에 적었다.

## 720 을 전제로 짜여 있던 자리 (지시 (3))

**UI 는 하나도 안 고쳐도 됐다** — 화면들이 전부 앵커(가운데/모서리 기준)로 짜여 있어서
캔버스가 커지자 그대로 따라왔다. 실제로 고친 것은 이것들이다:

| 무엇 | 왜 |
|---|---|
| `world_range_probe.gd` 의 `±640, ±360` | 손으로 적힌 값이라 논리 해상도와 따로 놀았다 → `BASE_SIZE` 에서 끌어오게 했다 |
| `qa_settings.gd` · `qa_world_entry.gd` 의 `EXPECTED_RANGE` | 같은 이유. 이제 둘 다 `BASE_SIZE` 에서 계산한다 |
| `qa_player_appearance.gd` 의 `CROP * size.x / 1280` | 논리 폭을 손으로 적어둔 자리 → `get_visible_rect()` 로 |
| `world_gen.gd` · `aim_line.gd` · QA 주석 여러 곳 | 「가로 9.6 화면」 → 8.5, 「화면 세로 720」 → 810 |

**조준선 길이 260 은 안 바꿨다.** 월드 단위 값이라 논리 해상도와 무관하고("몇 타일
앞"이지 "화면의 몇 %"가 아니다), 근거로 적힌 *"사거리 800 을 그리면 화면을 통째로
가로지른다"* 는 810 에서도 그대로 참이다(카메라가 캐릭터에 붙어 있어 세로 반은 405 다).
`DESIGN.md` 표의 근거 문구만 고쳤다.

## 어려움 / 에러와 해결 — **자체 QA 6벌이 무너졌고, 원인은 두 가지였다**

바꾸자마자 `qa_bullets` · `qa_death_box` · `qa_hotbar` · `qa_inventory` · `qa_map` ·
`qa_world_entry` 가 깨졌다. **바꾸기 전 트리로 되돌려 돌려보고 「원래 초록이었다」를
먼저 확인**한 뒤 원인을 갈랐다.

**(1) 마우스 좌표의 공간이 둘로 갈렸다.** `Input.warp_mouse()` 와
`parse_input_event()` 는 **창 픽셀**을 받는데, 검사가 재는 자리(Control 의 `global_rect`,
`get_mouse_position()`)는 **논리 좌표**다. **전에는 두 값이 같아서 이 버그가 안 보였다.**
→ QA 마다 `_to_window()`(= `root.get_screen_transform() * 점`)를 두고 넘기기 전에 한 번
변환한다. 이 변환은 배율뿐 아니라 16:9 아닌 창의 **여백 오프셋**까지 처리한다.
- 그 과정에서 **공간을 두 번 변환하던 자리**도 찾았다: `_aim_at()` 이 `origin` 을
  `DisplayServer.window_get_size()`(창 픽셀)로 잡아놓고 그걸 다시 논리→창 변환했다.
  주석에 *"논리 해상도와 창 크기가 같다는 전제다"* 라고 적혀 있던 자리다 → 논리 좌표로
  통일했다.

**(2) 배율이 1 이 아니면 화면 픽셀을 짚는 검사가 무너진다.** 창 1280×720 에 논리
1440×810 이면 배율이 0.889 라, 1px 짜리 「고른 칸」 테두리가 downscale 에 뭉개지고
지도 타일 색이 이웃으로 번진다(안 가본 칸 6351개가 「보인다」고 나왔다).
→ **자체 QA 는 창을 논리 해상도와 같게 맞춰 놓고 돈다.** 검사할 것은 「로직과 배치」이지
「축소했을 때의 흐릿함」이 아니고, **해상도 네 개에서의 공정성은 `qa_settings` 가 따로
본다.** 다만 메인 메뉴가 뜰 때마다 `apply_saved()` 가 창을 되돌리므로 한 번 맞춰서는
안 되고 `_process` 에서 지킨다.

**(3) 그 지키는 코드가 처음엔 오히려 검사를 불안정하게 만들었다.** 크기를 되돌린 그
프레임에 바로 다음 단계가 돌아서, 반영되기 전에 마우스를 밀었다. 처음엔 「8프레임
대기」로 막았는데 **수직동기화가 꺼진 창에서는 8프레임이 몇 ms 라 대기가 아니었다** —
`docs/GOTCHAS.md` 가 이미 경고하던 함정이다. **초 단위(`SETTLE_SECONDS`)로 바꾸니
없어졌다.** 창은 늘 기본 크기로 열리므로 이 대기는 **매 실행 첫 프레임에 반드시 한 번**
일어난다.

**반복 실행으로 확인했다** — 고치기 전에는 3바퀴 중 2바퀴가 실패했고(기준선 트리도
`qa_hotbar` 가 한 번 실패해서 **원래 있던 불안정**과 갈라 봤다), 고친 뒤에는 전체
스위트 5바퀴 + 드래그 검사 반복 9회가 전부 통과했다.

## `docs/GOTCHAS.md` 에 넣은 것 (128 → 138줄)

위 (1)(3)은 이 프로젝트의 규칙이 아니라 **「Godot 이 이렇게 동작한다」**라서 제자리가
거기다. 넣기 전에 파일을 훑어 겹치는 항목이 없는 것을 확인했다.

- `warp_mouse`/`parse_input_event` 는 창 픽셀, `get_mouse_position()`/`global_rect` 는
  논리 좌표 — `get_screen_transform()` 으로 한 번만 변환할 것.
- `window_set_size()` 는 즉시 반영되지 않는다 — 초 단위로 쉰 뒤 다음 단계를 돌릴 것.
