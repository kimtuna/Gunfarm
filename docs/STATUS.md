## 원인은 마스크의 세기가 아니라 「마스크를 뺀 것」이었다

옛 식은 `노이즈 × 2.5 + 0.70 − 거리³ > 0` 이었다. 노이즈를 실제로 재보니 표준편차
0.253 이라 `노이즈 × 2.5` 는 **±1.9** 를 오가는데, `거리³` 은 거리 0.5 에서 겨우
**0.125** 다. **지도 안쪽 80% 에서는 감쇠가 없는 것과 같아서**, 그 구역이 통째로
"땅이 될 확률 87%짜리 동전던지기"가 됐다 — 그게 「풀밭에 구멍이 뚫린 모양」의 정체다.
감쇠는 테두리 근처에서만 일해서, 결과는 섬이 아니라 **네모로 잘린 대륙**이었다.

**그래서 세기를 키우지 않고 연산을 바꿨다 — 빼는 대신 곱한다.**

| | 옛것 | 지금 |
|---|---|---|
| 식 | `노이즈 × 2.5 + 0.70 − 거리³ > 0` | `높이 × 마스크 > 0.10` |
| | | `높이 = clamp(0.5 + 노이즈 × 1.3, 0, 1)` |
| | | `마스크 = clamp(1 − 거리 ÷ 1.02, 0, 1)` |
| 육지 덩어리 | 28~51개 | **1개** |
| 갇힌 물 | 2100~6600칸 | **0칸** |
| 바다 | 45~48% | **51~56%** |
| 앞바다 여백 | 4칸 (테두리에 붙는다) | **11~12칸** |
| 해안선 ÷ 같은 넓이 원 | — | **2.00~2.79** |
| 월드 하나 만드는 시간 | 약 180ms | 약 **160ms** |

- **곱하면 마스크가 0 인 바깥은 노이즈가 아무리 높아도 바다**라, 앞바다 여백이 실측이
  아니라 계산으로 보장된다.
- **반지름을 잘라내는 방식(어떤 거리부터 무조건 바다)은 만들어 보고 버렸다.** 섬이 그
  반지름에 닿는 순간 해안선에 **매끄러운 원호**가 남는다 — 후보 그림에서 눈으로 확인했다.
  곱셈 마스크는 그 구간에서 「땅이 될 확률」만 낮추므로 해안선이 노이즈 모양 그대로 끝난다.
- **노이즈에서 남는 조각섬과 웅덩이는 지형을 두 번 훑어 없앤다** — 가장 큰 육지 덩어리만
  남기고(걸어서 못 가는 땅을 없앤다), 테두리에서 물길로 못 닿는 물을 땅으로 메운다
  (`_keep_only_main_island` / `_fill_enclosed_water`). 둘 다 시드에서 나온 지형만 보므로
  **재현성은 그대로다**(실행 사이 지문 비교 통과).
- 그림: `docs/design_reference/world_island_before_after.png` (윗줄 옛것 / 아랫줄 지금 것).

## 파라미터는 후보를 구워 나란히 놓고 골랐다

주파수 · 감쇠 지수 · 노이즈 대비 · 섬 반지름 · 문턱을 **90여 조합** 돌려서
바다비율 / 해안선복잡도 / 갇힌물 / 육지덩어리수 / 앞바다여백 / 시드간차이를 표로 뽑고,
후보 그림을 10시드씩 나란히 봤다.

**섬 실루엣을 시드마다 크게 다르게 만드는 것은 재보고 포기했다.** 낮은 주파수 노이즈로
섬의 반지름을 방향마다 늘이면 길쭉한 섬·큰 반도가 나오는데, **늘어난 쪽이 지도
테두리에 닿는다.** 여백을 지키려면 섬을 그만큼 작게 잡아야 해서 실측으로
**지도의 10% 가 통째로 빈 바다가 되는 대신 시드 사이 차이는 3%p 느는 데 그쳤다.**
안쪽으로만 뒤트는(만만 깊어지는) 변형도 재봤는데 바다 4~8%p 를 더 쓰고 차이는 +0.4~2%p 였다.
플레이어가 실루엣 전체를 보는 것은 지도 화면뿐이고, 화면에서 실제로 읽히는 것은
만·후미·곶이다 — 그쪽은 해안선 비 2.0~2.8 로 확보돼 있다. 근거는 `DESIGN.md` 에 남겼다.

## 자체 판단으로 정한 것

**(1) 「해안선 복잡도」의 잣대를 바꿨다.** 옛 기준(바다에 닿은 땅 칸 ÷ 전체 땅 칸,
합격선 7%)은 **섬이 클수록 저절로 작아지고**(둘레는 반지름에, 넓이는 제곱에 비례),
무엇보다 옛 지도에서 10% 가 나왔던 것은 해안선이 복잡해서가 아니라 **육지에 뚫린 웅덩이
테두리가 전부 「해안」으로 세어졌기 때문**이다 — 웅덩이를 메우자마자 같은 섬이 4~6% 로
떨어진다. **합격선을 낮추는 대신 잣대를 「해안선 길이 ÷ 같은 넓이 원의 둘레」로 바꿨다**
(완전한 원이면 1.0, 지금 2.00~2.79, 합격선 1.60). 넓이로 정규화해서 섬 크기와 무관하다.

**(2) 호수를 남기지 않고 전부 메웠다.** 항목이 요구한 것은 "육지를 하나의 섬으로 뭉치고
바깥을 바다로 두른다"이고, 물이 전부 바깥 바다 하나면 그 문장이 **검사 가능한 명제**가
된다(테두리에서 못 닿는 물 = 0칸). 「낚시」는 물 자체가 낚시터라 해안이면 되고,
*"서식지에 따라 잡히는 물고기가 달라진다"* 는 아직 물 종류가 하나뿐이라 민물/바닷물을
가를 기준이 없다. **서식지 구분이 생기는 바퀴가 되살릴지 다시 판단한다** — 그때는 메우는
대신 크기 하한을 두면 된다. `DESIGN.md` 에 그렇게 적어뒀다.

**(3) 바다 비율이 47% → 51~56% 로 늘어난 것을 되돌리지 않았다.** 되돌리려면 섬을
키워야 하는데 그러면 앞바다 여백이 11칸 → 6칸으로 줄어 「두른 바다」가 얇아진다.
땅은 지도의 47% → 45% 로 2%p 줄었을 뿐이라(약 29,000칸 = 가로로 8화면) 놀 자리는
그대로다. 합격선은 46~62% 로 갱신했다.

**(4) 스폰 로직은 한 줄도 안 건드렸다.** 「가장 큰 육지 덩어리 안에서 중심에 가장 가까운
칸」이 그대로 맞고, 이제 덩어리가 하나뿐이라 저절로 본섬이다. 실측 스폰은 전 시드에서
(127~128, 127~128) 이고 주변 8칸이 전부 땅이다.
