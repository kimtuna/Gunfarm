## 만든 것

- **`gun_ammo.gd` — 탄창 코어**(노드를 안 무는 순수 클래스). **탄종마다 탄창이 따로**
  (`rounds` 가 탄종 → 발수)이고, `fire()` 가 **실제로 한 발을 덜어냈을 때만 true** 를
  돌려준다 — "다 쏘면 좌클릭해도 안 나간다"가 그 한 줄에서 나온다. 재장전은 90틱(1.5초)
  짜리 카운터이고, 프레임 시간을 안 받는 `tick()` 이 `player_motion.tick()` 안에서 돈다.
- **`gun_hud.gd` — 총 UI.** 탄종 이름 + 남은 발수 + **탄창 8칸**. 상태를 하나도 안 들고
  플레이어 코어의 `gun` 을 읽어 그리기만 한다. 자리는 하단 핫바 바로 위, 화면 가운데다.
- **`player_motion.gd` 가 탄창을 들고 있다**(`gun`). 남은 발수와 든 탄종은 화면 상태가
  아니라 **플레이어 상태**다(「서버 권위」). R/우클릭은 `player_input.gd` 에 실려 오고,
  코어는 **눌린 틱 하나**만 표시한다(`reload_started` / `switch_started`).
- **`world.gd` 가 총을 들었는지 판정한다** — 좌클릭·R·우클릭 셋 다 `_held_item_id()`
  하나를 지나간다(인벤토리를 가진 쪽이 본다).
- `project.godot` 에 액션 두 개(`reload` = R, `switch_ammo` = 우클릭).
- **`qa/qa_gun_ammo.gd`** — 코어 6가지 + 화면 5가지. 캡처 6장.

## 스스로 판단해서 고친 부분

- **재장전 시간을 1.5초로 정했다.** 「총기 스탯」이 "약간의 시간 소요"라고만 정해둔
  값이라 골라야 했다 — **연사 간격(0.5초)의 세 배**다. 더 짧으면 쏘는 리듬이 안 끊겨
  탄창이 있으나 마나가 되고, 훨씬 길면 8발을 4초에 비우고 재장전을 더 오래 기다리게
  되어 사냥이 기다림이 된다. 근거를 `DESIGN.md` 「총기 스탯」에 적었다.
- **탄종을 바꾸면 진행 중이던 재장전이 취소된다.** 문서가 전환을 "다른 탄창으로 갈아
  끼우는 것"이라고 정의했으니, 손에서 내려놓은 탄창이 저 혼자 채워지고 있으면 안 된다.
- **탄창 상태를 저장하지 않는다.** 예비 탄약이 없어 R 한 번이면 되돌아가는 값이라
  저장 포맷을 늘려서 지킬 이유가 없다(날아가는 총알과 같은 판단이고, 근거를 적었다).
- **탄창이 비어도 사용 모션은 그대로 나온다.** 모션을 트는 코어는 손에 든 것이 무엇인지
  모르고(칸 번호까지만 안다), 총알을 만드는 것은 인벤토리를 아는 쪽이다 — 여기서 모션까지
  막으려면 코어에 "이건 총이다"를 넣어야 하는데 그게 「서버 권위」가 막아둔 것이다.
  못 쐈다는 것은 총 UI 의 **빈 탄창 + 빨간 0 / 8** 이 말한다.
- **탄종 id 를 아이템 id 그대로 썼다**(`ammo_basic` / `ammo_tranq`). UI 가 이름·색을
  `item_types.gd` 에서 그대로 읽어서 두 곳이 어긋날 자리가 없다. **총이 탄약 아이템을
  소비하지는 않는다** — 「새 테크 라인」이 그 연동을 범위 밖이라고 못 박아뒀다.
- **총 UI 를 켜고 끄는 판정을 조준선과 같은 한 줄에 뒀다.** 따로 갈리면 총을 내렸을 때
  한쪽만 남는다.
- **재장전 표시를 진행 막대가 아니라 "칸이 왼쪽부터 차오르는 것"으로 만들었다.** 탄창이
  채워지는 그림 자체가 진행도라 새 요소가 필요 없고, 다 차오른 순간이 곧 다시 쏠 수
  있게 되는 순간이라 둘이 어긋날 자리가 없다.
- **R/우클릭을 `world.gd` 에서 바로 처리하지 않고 입력(`player_input.gd`)에 실었다.**
  `apply_recoil()` 처럼 밖에서 부르는 쪽이 더 짧았지만, #35(5)가 "남은 발수와 든 탄종은
  플레이어 상태"라고 못 박았고 좌클릭(`use`)이 이미 그 길로 가고 있어서 같은 길로 맞췄다.

## 어려움 / 에러와 해결

- **탄창을 비우는 검사가 한 발을 잃었다.** 좌클릭 여덟 번을 `쏘기 → 기다리기` 순으로
  넣었더니 **첫 발이 바로 앞 발사의 0.5초(`USE_TICKS`) 안에 들어가** 코어가 겹쳐 쓰기를
  막았다. `기다리기 → 쏘기` 로 뒤집어 해결했다.
- **검사 순서가 뒤집혀 거짓 실패가 났다** — 탄창 칸 색을 재기 **전에** "칸을 찾았는가"를
  보고 있었다. 두 단계를 바꿔 해결했다.
- **`var filled := gun.loaded()` 가 파싱 에러를 냈다** — `gun` 이 `RefCounted` 라 타입이
  추론되지 않는다(`docs/GOTCHAS.md` 에 이미 있는 함정이라 바로 찾았다). 타입을 직접 적었다.
- 자체 QA **20개 전부 PASS**(엔진 ERROR 0건). 이웃 검사도 전부 다시 돌렸다 —
  `qa_bullets` / `qa_hotbar` / `qa_world_entry` / `qa_player_world` / `qa_inventory` /
  `qa_map` / `qa_ground_items` / `qa_uid_files` 전부 PASS.
- 캡처를 눈으로 확인했다 — 가득(기본탄 8/8, 놋빛 탄피 8칸) / 도끼를 들면 UI 와 조준선이
  같이 사라진 것 / 한 발 쓴 것 / 빈 탄창(빨간 0 / 8) / 재장전 중 첫 칸이 차오르는 것 /
  마취탄(녹색 8칸)까지 다 보인다.
