## 만든 것

- **`map_canvas.gd` 에 줌이 들어갔다.** 그림(256×256 이미지)은 그대로 두고 **붙이는
  사각형(`map_rect()`)만** 바꾼다 — 배율이 바뀌어도 65,536칸을 다시 굽지 않는다.
  - 정수 배율 1/2/4/8만, 휠 한 칸에 한 단계, 양 끝에서 멈춘다. 사각형의 시작 좌표를
    정수로 반올림한다(소수가 남으면 배율이 정수여도 지도 픽셀이 2px/3px 로 들쭉날쭉해진다).
  - 창(512×512)보다 커지는 4·8배에서는 **플레이어를 한가운데 두고 자르되**, 지도
    가장자리에서는 `clampf` 로 중심을 안쪽으로 물려 지도 밖이 안 나오게 한다.
  - **줌 값은 `map_canvas.gd` 의 static 변수 하나**다. 지도 노드는 닫을 때 사라지므로
    노드에 두면 안 남고, 슬롯에 두면 저장돼 버린다 — "닫았다 열어도 유지, 게임을
    다시 켜면 기본 2배"가 이 자리에서 그대로 나온다(슬롯 저장은 손대지 않았다).
- **휠은 `map_screen.gd` 의 `_input` 이 받아서 바로 소비한다**(`set_input_as_handled`).
  지도가 떠 있는 동안에만 이 노드가 트리에 있어서 "지도가 열려 있을 때만"이 저절로
  성립하고, 나중에 붙을 핫바 스크롤로 새지 않는다. 눌림/뗌 둘 다 먹는다.
- **`qa_map.gd` 를 넓혔다** — 네 배율의 크기/중심/은닉/귀퉁이/휠 범위/유지까지.
  캡처는 `54_zoom_1x` ~ `59_zoom_corner_3`.

## 스스로 판단해서 고친 부분

- **1배에 지도 가장자리 선(창틀과 같은 금색 한 줄)을 그었다.** 지시에 없던 것인데,
  1배에서는 지도(256px)가 창(512px)보다 작아 여백이 생기는데 **여백색과 "안 가본 칸"
  색이 둘 다 어두워서 세계가 어디서 끝나는지 화면으로 구분이 안 됐다**(첫 캡처를 보고
  알았다). 지도 **바깥쪽**에 그어서 가장자리 한 칸을 덮지 않는다.
- **검증 방법을 API 값이 아니라 화면 픽셀로 잡았다.** `map_rect()` 가 무엇을 돌려주든
  실제로 칠해진 넓이가 N배가 아니면 걸리게 했다 — 1배는 여백과의 경계까지 재서 가로폭
  (256px)을, 2배 이상은 지도 한가운데에 **홀로 찍힌 방문 동그라미**의 세로 길이를 잰다
  (그래서 줌 검사는 "아직 아무것도 안 적힌 육지"를 찾아가 그 위에서 한다).
- **`clip_contents` 를 켰고, 그걸 잡는 검사도 넣었다.** 처음엔 창 **안쪽** 픽셀만 봐서
  `clip_contents` 를 꺼도 QA 가 통과했다 — 실제로는 8배 지도가 창틀·제목·월드 화면까지
  통째로 덮고 있었다(캡처로 확인). 창 **바깥** 픽셀도 짚도록 검사를 고쳤다.

## 어려움 / 에러와 해결

- **이가 있는지 일곱 가지로 확인했다** — 전부 FAIL 나는 것을 보고 원본을 되돌렸다.
  1. 줌을 무시하고 늘 창 크기로 그리기 → 크기·가로폭·동그라미·중심 4종 FAIL.
  2. 가장자리 클램프 제거 → 귀퉁이 4곳 전부 FAIL(지도 밖 800/1089자리).
  3. `set_input_as_handled()` 제거 → "휠이 지도 뒤까지 흘러갔다" FAIL.
  4. 열 때마다 배율 초기화 → "닫았다 열었더니 2배로 돌아갔다" FAIL.
  5. 확대해도 플레이어를 안 따라가게 → 4·8배 "한가운데가 아니다" FAIL.
  6. 안 가본 칸도 그리기 → 네 배율 모두 "안 가본 칸이 보인다" FAIL.
  7. `clip_contents` 끄기 → 4·8배 "자기 창 밖으로 넘쳐 그려졌다" FAIL.
- **휠이 새는지 보는 검사는 감시자(`WheelSpy`)가 고장 나도 통과할 수 있다.** 그래서
  지도를 **닫고** 돌린 휠은 반대로 감시자에 잡혀야 한다는 것까지 같이 본다.
- `qa_map` 3회 연속 PASS, `qa_world_entry` PASS, `qa_uid_files` PASS. 캡처 1/2/4/8배와
  귀퉁이 4장을 눈으로 확인했다.
