## 원인 — 항목이 짚은 세 갈래 중 어느 것도 아니었다

**게임 코드는 한 줄도 안 고쳤다. 정렬은 원래부터 맞았다** — 고장난 것은 검사가
아이템을 **놓는 자리**다.

`_check_sort_order()` 는 아이템을 플레이어 위/아래로 **같은 거리**(`SORT_OFFSET` 10px)
옮겨 놓고 겹친 픽셀을 센다. 그런데 **플레이어 그림은 노드 원점(발밑)보다 위쪽에만
있다** — 원점 아래는 그냥 땅이다. 그래서 두 방향이 딴판이다:

| 옮긴 거리 | 겹친 픽셀 |
|---|---|
| 위(뒤)로 −6 / −10 / −30 | 276 / **281** / 429 |
| 아래(앞)로 +1 / +4 / +6 / +10 / +14 / +22 | 195 / **150** / 126 / **75** / 34 / 0 |

위로 옮기면 아이템 그림이 정강이·무릎으로 올라가 넓게 겹치고 **멀수록 는다**.
아래로 옮기면 발목만 스치고 **1px 내려갈 때마다 12px 씩 준다.** 한 값으로 묶어두면
한쪽이 반드시 굶는다 — 지금까지는 캐릭터가 통통해서 10px 로도 둘 다 넘겼을 뿐이다.

## 무엇을 바꿨나

`game/qa/qa_ground_items.gd` 한 파일.

- `SORT_OFFSET`(10) → **`SORT_OFFSET_BEHIND`(10) / `SORT_OFFSET_FRONT`(4)**.
  뒤쪽은 손대지 않았다(281px). 앞쪽만 4px 로 당겨 **150px** 을 만든다 — 하한 100 의 1.5배다.
- **`SORT_MIN_PIXELS`(100)은 그대로다.** 항목이 (다)를 마지막 수단으로 둔 이유가
  "그 숫자는 「아이템이 통째로 안 보인다」를 잡는 벽이기도 하다"였는데, 그 벽을
  안 건드리고 통과한다.
- 실패 메시지에 **어느 방향이 굶었는지**를 같이 적게 했다. 위/아래는 겹치는 양이
  딴판이라 숫자만 봐서는 어느 값을 손봐야 하는지 알 수 없다(이번에 실제로 그랬다 —
  "83px 뿐이다"만 보고 아이템 그림 탓으로 읽혔다).

## 실측으로 반증한 것 — 다음 바퀴가 다시 안 해보게

**(나) "캐릭터가 가로로 5px 밀려 있다"는 사실이지만 이 실패의 원인이 아니다.**

## 새로 넘긴 것 — INBOX #71

(나)를 재다가 **원인까지 찾았다**: `rig.py` 의 `bake_rows()` 가 자를 상자를 **몸
테두리의 한가운데**에 맞추는데, 그 테두리에 **뻗은 팔이 들어간다.** 도구를 든 자세는
오른팔이 옆으로 나가므로 중심이 오른쪽으로 밀리고 **몸통·다리는 왼쪽으로 밀린다.**

- 실측(다리 띠의 한가운데가 96px 칸의 중심에서 떨어진 거리): `player_idle_farmer` 는
  네 방향 다 ±0.5px 인데 `player_hold_*` `player_walk_*` `player_use_*` 는 **정면
  −5.5 ~ −7.5px, 뒷모습 −5.0 ~ −7.0px** 다. 옆모습만 멀쩡하다(팔이 앞뒤로 겹쳐서
  테두리가 안 넓어진다).
- 즉 **빈손 ↔ 도구를 오갈 때 캐릭터가 6px 옆으로 순간이동한다.**
- 고칠 자리는 `bake_rows()` 의 `cx` — 테두리 한가운데가 아니라 **선 축**(`J['hipC']`
  의 x 나 두 발의 가운데)이어야 한다. 그 함수의 주석이 이미 그렇게 하고 싶다고
  적어놓았다. **22장을 다시 굽는 일이라 이번 항목 범위 밖이다.**
