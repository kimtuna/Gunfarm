## 스스로 판단해서 고친 부분

- **뚜껑이 열린 프레임을 따로 구웠다**(INBOX #40 (3) 이 판단에 맡긴 것이다). 예전의
  「테두리가 밝아지는 것」은 그림이 아니라 월드 위에 뜬 UI 로 보였다 — 타이머가 멈춰
  있다는 것을 **그림 자체가** 말해야 한다. 두 프레임을 실제로 나란히 놓고 확인했다.
- **INBOX #40 (4) 의 미정을 정했다**: 「건축」의 설치형 상자와 **실루엣을 나눠 쓰지
  않는다.** 근거는 `DESIGN.md` 에 적었다 — 둘은 규칙이 정반대인데(타이머 있음/없음,
  꺼내기만/양방향) 같은 그림이면 "여기 넣어도 되나"를 그림으로 구별할 수 없고,
  **남은 시간 막대로는 갈리지 않는다**(「사라지지 않음」이면 막대가 아예 안 그려진다).
- **재질을 새로 늘리지 않았다.** 자물쇠를 금색으로 뽑을까 했지만, 새 램프는
  커스터마이징 팔레트 교체와 검사 표를 동시에 늘린다 — 나무·쇠 두 램프는 이미
  고정색이고 도구와 **정확히 같은 색**이라 「어울림」이 공짜로 지켜진다.
- **판자 결을 넣었다.** 판자 없이 구운 후보는 통나무/술통으로 읽혔다. 부위 id 만 다른
  조각을 겹쳐 `inner_lines()` 가 경계에 어두운 줄을 긋게 했다(뒷머리 결과 같은 수법).
- **쇠 띠를 한 칸에서 두 칸으로 굵혔다.** 「재질명도」가 쇠 평균 150(하한과 같은 값)
  으로 잡았는데, 얇은 쇠붙이가 축소하면서 어두워지는 것은 이미 아는 사실이라
  **검사를 늦추지 않고 그림을 고쳤다**(낚싯대 「명암폭」 때와 같은 판단이다).
  실측 0.55 → 150 / 0.70 → 151 / 0.85 → 158 / 1.00 → 164(1.00 은 띠가 상자를 반으로
  가른다) — 통과 구간의 가운데를 골랐다.
- **자체 QA 가 상자를 여는 방식을 둘로 갈랐다.** 좌클릭으로 열면 **창이 화면을 덮어서**
  뚜껑을 픽셀로 볼 수가 없다 — 그림을 보는 단계에서는 코어(`boxes.open()`)만 열고,
  좌클릭 경로는 예전대로 창이 뜨는지로 본다.

## 어려움 / 에러와 해결

- **열린 상자의 "구멍"을 조명으로는 못 만들었다.** 가파른 면을 세워 광원을 등지게 해도
  `light()` 의 환경광(`CFG["amb"]` 0.17) 때문에 명도가 0 까지 안 내려가서 **램프 4단계
  중 3단계(그늘)가 하한**이다(가장 어두운 단계는 `inner_lines()` 만 찍는다). 그렇게
  구운 후보 다섯 개가 전부 "뚜껑이 하나 더 얹힌 상자"였다. **구멍은 재질이 아니라
  재질이 없는 자리**라 공통 잉크색으로 찍었고(외곽선이 잉크인 것과 같은 이유),
  잉크만으로는 검은 스티커가 되므로 그 아래에 **가장 어두운 나무 한 켜**를 두어 깊이를
  만들었다. 이 사실은 `docs/STYLE_GUIDE.md` 로 옮겼다.
- **칸이 정사각형이 아닌 첫 자산이었다.** `gen_character.canvas()` 는 정사각만 만들고
  `qa_sprite_check.py` 도 `cell` 하나로 세로·가로를 같이 쟀다. 생성기는 **16 × 16 에
  굽고 아래 두 줄을 잘라내는** 쪽으로(캔버스 코드를 뜯지 않았다), 검사는 `cell_h` 한
  줄을 더하는 쪽으로 풀었다.
- **새 검사가 실제로 잡는지 거짓 실패로 확인했다** — (1) 노드가 항상 닫힌 프레임을
  그리게 하면 「열린 프레임이 아니다」로, (2) 그림을 한 도트 옆으로 밀면 「그림이
  밀렸거나 배율이 다르다」로 각각 FAIL 이 났다. 그러고 나서 되돌렸다.
- 자체 QA **전부 PASS**: `qa_sprite_check.py`(104항목, `death_box.png` 포함) + 엔진 쪽
  21개(`qa_death_box` / `qa_uid_files` / `qa_ground_items` / `qa_inventory` /
  `qa_hotbar` / `qa_player_sprite` / `qa_player_walk` / `qa_character_sprite` /
  `qa_player_appearance` / `qa_terrain_view` / `qa_world_gen` / `qa_slot_store` /
  `qa_health` / `qa_gun_ammo` / `qa_bullets` / `qa_map` / `qa_player_world` /
  `qa_world_entry` / `qa_settings` / `qa_main_menu` / `qa_character_slots` /
  `qa_character_customize`).
- 캡처를 눈으로 확인했다 — 풀밭 위의 상자가 캐릭터·바닥 도끼와 **같은 도트 결·같은
  나무색**이고, 닫힘/열림이 실제 게임 크기(48 × 42)에서 한눈에 갈린다.
- **`docs/GOTCHAS.md` 는 119줄 그대로다** — 이번에 부딪힌 것은 "Godot 이 이렇게
  동작한다"가 아니라 전부 그림 쪽 사실이라 `docs/STYLE_GUIDE.md` 로 갔다.
  **150줄 상한까지 여유가 줄고 있다는 메모는 계속 유효하다.**
