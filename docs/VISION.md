# VISION.md — 장기 비전 메모 (얼리억세스 이후)

> **이 파일은 매 바퀴 읽지 않는다.** 지금 당장 설계/구현할 대상이 아니고, 얼리억세스
> 발매 이후에나 착수할 내용이라 지금 INBOX 항목과 부딪힐 일이 없다. 장기 로드맵을
> 실제로 설계하기 시작할 때만 참고한다.

게임의 핵심 정체성과 장기 로드맵을 잊지 않기 위해 기록해둔다. 세부는 전혀 정해지지
않았다.

- **핵심은 "자동화 공장의 힐링"** — 1차 목표는 힐링(느긋한 자동화/파밍), 그 위에 아래
  경쟁·협동 요소가 얹히는 구조.
- 지금의 싱글/세션서버 구조에 더해 **중앙 서버 + 매칭 시스템**을 나중에 추가할 계획.
  참고 게임: **딥록 갤럭틱**(협동해서 함께 탐사) 느낌의 **PvE 우선** 구조 — 자신의
  섬(세션서버)에 다른 사람을 초대해 파티를 이루고, 희귀 자원이 있는 별도의 "섬"으로
  함께 이동해서 파밍한다.
- PvP를 도입한다면 **강제가 아니라 허용 지역**(아크 서바이벌/타르코프처럼 — 싸워도
  되지만 안 싸우고 탐험만 해도 됨) 방식으로 구상 중.
- 경쟁 구도는 "누가 더 많이 가져가냐"가 아니라 **자신이 직접 만든 장비(총/갑옷/버프
  음식 등)로 도전하는 것 자체**가 목적 — 희귀 자원 파밍 결과물은 **경매 방식으로
  파티원끼리 분배**하는 것도 검토 중(참고: 로스트아크 보스 레이드 분배 방식, 인원수는
  섬당 정원 기준, 예: 4인).
- **테크 진행은 의도적으로 매우 느리게**, 버프 음식 등도 구하기 어렵게 만들 계획 —
  성취감을 위해 초반 자동화를 지양한다는 기존 "탑다운 레벨" 철학과 같은 맥락.
- **장비(총/갑옷/도구 전부)에 스탯 + 인챈트 시스템**을 붙여 성능을 강화하는 구조를
  구상 중(참고: 마인크래프트 인챈트).
- **플레이어 간 거래소(경매장)**를 나중에 만들 계획 — 참고: 메이플스토리 경매장. 스팀이
  지원하는 기능을 쓸지, 직접 웹사이트를 만들어 운영할지는 미정.
- 더 나중에는 **스탯/장비 퀘스트를 통한 대장장이·요리사 등 칭호/스킬** 시스템으로 확장,
  외부 유저의 "의뢰"를 받는 것까지 구상 중.
- 이 전체 방향은 지금의 "호스트 겸용 리슨 서버 + 방 코드" 구조와 별개의, 훨씬 큰
  인프라(중앙 매칭 서버, 경매 서버/웹사이트 등)를 필요로 한다 — 핵 관련 우려도 있어
  실제 설계는 얼리억세스 이후 별도로 진행.

## 단계 로드맵 (무엇을 언제, 그리고 그때 무엇이 필요해지는가)

순서를 이렇게 잡는 이유는 **각 단계가 필요로 하는 인프라 비용이 다르기 때문**이다.
1~3단계는 개발자가 운영하는 실시간 게임 서버가 한 대도 필요 없다.

| 단계 | 만드는 것 | 그때 새로 필요해지는 것 |
|---|---|---|
| 1 | 생활 + 자동화 루프 (싱글) | 없음 |
| 2 | 친구 co-op (호스트 겸용 리슨 서버 + 방 코드) | 방 코드 중개/릴레이 서버 (작음) |
| 3 | **PvE 원정 섬** (딥록 갤럭틱 방향) | 중앙 원장·관문 (작음) |
| 4 | PvP 허용 지역 | 전용 게임 서버, 매치메이킹, 안티치트 |

- **3단계까지는 전부 유저 기계에서 돈다.** PvE 섬도 호스트가 열면 된다 — 호스트가 치팅해도
  피해자가 자기 자신뿐이라 남의 재미를 망치지 않는다. 유일한 실질 피해인 경제 오염은
  아래 "수출 상한"이 막는다.
- **4단계(PvP)만 유저 호스팅이 불가능하다.** 호스트가 참가자면 그 사람은 상대 위치를
  전부 알고 있다 — 시야 차단을 아무리 잘 만들어도 호스트 프로세스에는 전체 상태가 있어서
  우회할 방법이 없다. 그래서 PvP는 반드시 전용 서버여야 한다.
- **따라서 PvP는 자본금으로 만드는 게 아니라 판매 수익으로 만든다.** 3단계까지 완성해서
  유료로 출시하고, 팔린 돈으로 PvP 서버를 연다. 참고로 덕코프는 **싱글플레이 PvE만으로**
  성공했다 — PvP가 영영 안 와도 게임은 상품으로 성립한다. 4단계는 필수가 아니라 보너스다.

## 인프라 — 중앙은 "구경꾼"이 아니라 "관문"이다

실시간 게임 서버와 중앙 원장은 비용이 완전히 다른 물건이라 절대 뭉뚱그리지 않는다.

- **중앙이 하는 일**: 신원 확인(스팀 인증 티켓을 검증하면 계정 시스템을 직접 만들 필요가
  없다) / 아이템 발행과 원장 / 서버별 수출 상한 집행 / 반출·의뢰·방문 중 아이템을 잠가두는
  에스크로 / 서버 목록. 매치메이킹은 4단계(PvP)에 가서야 실제로 필요해진다.
- **중앙이 절대 하지 말아야 할 일**: 게임플레이 시뮬레이션, 실시간 연결 유지, **지연시간
  경로에 들어가는 것.** 중앙이 빨라야 할 필요가 생기는 순간 설계가 틀어진 것이다. 모든
  호출은 트랜잭션이고 재시도 가능해야 한다.
- **부하가 작다.** 농장 안에서 벌어지는 일은 원장을 건드리지 않고, 경계를 넘을 때만
  호출된다 — 플레이어 하루 20건 미만. 무료 티어~월 몇 천 원 수준에서 시작할 수 있다.
- **인증은 클라이언트가 원장에 직접 한다.** 호스트를 거쳐 인증하면 악의적 호스트가 남의
  신원을 위조할 수 있다. 클라이언트가 서명된 토큰을 받아 호스트에게 제시하는 구조로 간다.
- **원장이 내려가도 게임은 돌아가야 한다.** 오프라인일 때는 그 세션의 아이템을 `로컬 전용`
  으로 표시해 밖으로 못 나가게만 하고, 플레이 자체는 막지 않는다.

## 보안 — 신뢰 구역과 수출 상한

| 구역 | 신뢰도 | 방어 방식 |
|---|---|---|
| 클라이언트 | 0 | 아무것도 믿지 않음. 입력만 받음 (`DESIGN.md` "서버 권위" 참고) |
| 호스트 서버 (유저 PC) | 낮음 | **방어를 포기하고, 경계에서 검증한다** |
| PvP 전용 서버 (4단계) | 높음 | 완전 권위 |

- **대전제: 플레이어가 호스팅하는 서버는 지킬 수 없다.** 호스트는 자기 기계의 주인이라
  메모리를 고치고 세이브를 직접 열 수 있다. 거기에 안티치트를 넣는 건 연극이다. 그래서
  방향은 "막는다"가 아니라 **"가둔다"** 다.
- **정책 한 줄: 당신 서버에서 뭘 하든 자유다. 밖으로 나올 때만 검증받는다.** 이걸 숨길
  일로 여기지 말고 명시적인 기능으로 내세운다 — 마인크래프트/테라리아 계열 플레이어에게
  이미 익숙한 계약이고, 솔직해서 신뢰를 얻는 쪽이다.
- **재화를 두 계층으로 쪼갠다.** 내부 재화(씨앗·목재·일반 작물 등)는 검증하지 않는다 —
  복사해도 서버 밖으로 못 나간다. 경계 재화(원정 섬 재료·상위 제작품·거래 통화)만 중앙
  원장에 기록되고 발행량이 통제된다.
- **수출 상한이 실질적인 방어선이다.** 중앙은 각 서버가 밖으로 내보내는 양을 검증 가능한
  사실(접속 계정 수, 누적 플레이 시간, 완료한 원정 횟수)로 제한한다. 안에서 백만 개를
  복사해도 밖으로는 정상 속도만큼만 나간다 — 그 순간 복사할 이유가 사라진다.
- **중앙이 스탯을 재계산한다.** 호스트가 신고한 장비 수치를 믿지 않고, 등급과 재료로부터
  다시 계산해서 맞는지 본다. `DESIGN.md`의 **포인트 예산제**(총합이 등급의 함수)가 이
  검증을 산술 한 줄로 만들어준다.
- **아이템은 경계를 처음 넘을 때 중앙에서 발행되어 고유 ID를 받는다.** 원장에 기록이 없는
  아이템은 반입이 거부된다.
- **에임핵은 원리적으로 못 막는다** — 에임봇이 보내는 입력은 전부 합법적인 입력이라
  잘하는 플레이어와 서버 입장에서 구분되지 않는다. 다만 탑다운 2D는 수직 조준·반동
  제어·순간 플릭이 없어서 FPS보다 이득 폭이 훨씬 좁고, 서버측 시야 차단으로 정보 우위를
  없애면 남는 이점이 더 줄어든다. 대응은 통계 이상치 탐지 + 수동 밴으로 충분하다.

## 전설직업 — 생활 플레이어의 천장 문제

위에 적은 "대장장이·요리사 등 칭호/스킬"과 "외부 유저의 의뢰"를 구체화한 방향이다.
**해결하려는 문제는 하나다: 생활만 즐기는 플레이어가 최고 단계에 도달할 길이 없으면
"결국 전투를 강요당한다"고 느끼고 떠난다.**

- **전설직업은 매우 얻기 어려운 제작 전문 직업이고, 그 사람이 만든 물건을 다른 서버
  사람들이 찾아오게 만든다.** 참고: Star Wars Galaxies의 마스터 크래프터 — 전투를 한 번도
  안 한 제작 플레이어가 서버 최고 유명인이었다. 돈이 아니라 **명성과 정체성**을 주는 게
  핵심이다.
- **덤으로 푸는 문제**: 친구 4명짜리 세션 서버들이 서로 만날 이유가 없다는 문제. 전설
  제작자가 있으면 서버 사이에 사람이 오간다(참고: 동물의 숲 섬 방문).
- **승급 조건은 순수 생활 숙련으로 한다** — 특정 작물 최고 품질 n회, 자동화 라인 규모
  달성 같은 것. **원정 섬에 한 번도 안 가고 전설직업을 딸 수 있어야 한다.** 섬 재료는
  **최상위 티어 제작에만** 필요하게 하고, 그건 주문자가 지참한다. 근거: 승급 자체에 섬
  재료가 필요하면 이 시스템이 풀려던 문제가 그대로 남는다.
- **독점을 막는 방법은 쉽게 만드는 게 아니라 좁게 만드는 것이다.** 진짜 위험은 후발주자가
  직업을 못 얻는 것이 아니라, 얻어도 이미 검증된 제작자에게 주문이 몰려서 진입을 못 하는
  것(명성의 네트워크 효과)이다. 그래서:
  - **직업을 여러 갈래로 쪼개고 한 캐릭터가 하나만 갖게 한다** (총기공/방어구공/조리사/
    약제사/사육사 등). 전 분야 독점이 물리적으로 불가능해지고, 전설 제작자끼리도 서로를
    필요로 하게 된다. 신규 진입자는 비어 있는 분야를 노릴 수 있다.
  - **감쇠 타이머 같은 숙제는 만들지 않는다.** 최상위 제작마다 신선한 섬 재료가 필요하다는
    사실만으로 접속을 안 하는 제작자는 자연히 주문을 못 받는다 — 숙제는 힐링과 충돌한다.
  - **전수**: 전설 제작자가 다른 플레이어의 승급 조건을 일부 대신 채워줄 수 있게 한다.
    독점이 유통망으로 바뀌고, 친구 서버 구조에 잘 맞는 사회적 장치가 된다.
  - 반복 획득 시 확률이 올라가는 **천장(pity)** 도 함께 둔다 — 다만 이건 개인의 좌절을
    푸는 장치지 위의 시장 독점을 풀지는 못한다. 둘 다 필요하다.
- **의뢰 시스템의 진짜 문제는 밸런싱이 아니라 셋이다.**
  - **사기** → 에스크로가 필요하다. 위 "인프라"의 원정용 아이템 에스크로와 **같은
    시스템**이다. 소유 상태에 `의뢰중`을 하나 더 두면 된다.
  - **비동기** → 서버도 시간대도 다르다. 실시간 거래는 성립하지 않으므로 **주문서 게시 →
    수락 → 납품**의 우편 구조여야 하고, 양쪽이 동시에 접속해 있을 필요가 없어야 한다.
  - **가격을 아무도 모름** → NPC 상인이 하한선을 잡아준다. 바닥이 없으면 가격 발견이
    일어나지 않는다.
- **방문 시 안전 규칙**: 다른 서버를 방문한 사람은 상점/의뢰대만 쓸 수 있고 농장
  오브젝트에는 손을 못 댄다. 그리핑 방지 없이 서버를 열어두지 않는다.

## 위 내용과 기존 메모의 충돌 정리

- 위에 적어둔 **인챈트(마인크래프트 참고)** 구상은 그대로 두되, `DESIGN.md`의 "제작/강화는
  성공·실패가 아니라 품질 분포로" 원칙을 따른다 — **실패로 장비가 파괴되는 방식은 쓰지
  않는다.** 근거는 그쪽에 적어뒀다.
- 위에 적어둔 **PvP 허용 지역**(강제가 아닌) 방향은 유지한다. 다만 위 로드맵대로
  **PvE가 먼저고 PvP는 4단계**다 — 덕코프가 증명했듯 긴장감의 대부분은 "사람이 쏜다"가
  아니라 "잃을 수 있다"에서 온다.
